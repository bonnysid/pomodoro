# Выпуск и обновления Pomodoro

## Как это работает

Начиная с 0.2.3 Windows-приложение использует electron-updater и публичные релизы https://github.com/bonnysid/pomodoro/releases. Через 15 секунд после запуска выполняется проверка. С версии 0.2.6 найденное обновление скачивается в фоне. В настройках можно проверить вручную, посмотреть изменения и нажать «Перезапустить и обновить».

Установка начинается только по кнопке. Работающий таймер блокирует установку; после паузы состояние сохраняется. Если сохранение не удалось, установка откладывается. Закрытие настроек не мешает загрузке и оставляет обновление на потом. При ошибке сети загрузку можно повторить вручную. Данные лежат отдельно от программы в прежней папке Pomodoro.

На Windows используется тихая установка NSIS: приложение закрывается, обновляется без страниц мастера и открывается снова. В закреплённой версии electron-updater 6.8.9 это вызов quitAndInstall(true, true). Первое обновление с 0.2.5 или старше ещё запускает мастер, потому что его запускает старый код. При установке для всех пользователей Windows может запросить права администратора; тихий режим не обходит системные разрешения.

В исходниках и браузерном предпросмотре обновления отключены. Для проверки реального источника нужен установленный выпуск. Старую версию 0.2.2 нужно один раз заменить вручную на 0.2.3.

## Код и релизы в одном репозитории

- Ветка main содержит исходники; node_modules, пользовательские данные, сертификаты и готовые сборки не коммитятся.
- При push в ветку запускаются проверки качества.
- Тег vX.Y.Z запускает Desktop releases. Версия тега должна совпасть с package.json.
- Windows и macOS собираются отдельными заданиями. После успешной сборки обоих вариантов создаётся черновик релиза, загружаются установщики и метаданные, затем релиз публикуется.
- Если загрузка оборвалась, остаётся черновик: повторный запуск может закончить его. Уже опубликованный релиз не перезаписывается.
- Ручной запуск Desktop releases без тега только собирает артефакты, не публикуя релиз.

Публикация использует встроенный GITHUB_TOKEN с contents: write только в задании publish. Создавать отдельный токен для этого репозитория не требуется. Сборочные команды используют --publish never: публикацией управляет завершающее задание.

## Следующий выпуск

1. Изменить код и docs/release-notes.md.
2. Выполнить npm version patch --no-git-tag-version (или minor/major по смыслу).
3. Выполнить npm run verify и npm run build.
4. Закоммитить изменения и отправить main.
5. Создать тег, совпадающий с новой версией, например git tag v0.2.4, затем git push origin v0.2.4.
6. Дождаться успешного Desktop releases во вкладке Actions. В Releases появится готовая версия.

Для Windows публикуются EXE, latest.yml и blockmap. Для macOS — DMG, ZIP, latest-mac.yml и blockmap. Файлы latest*.yml создаёт electron-builder; вручную их писать нельзя. Не помечать стабильный выпуск prerelease. Не переносить репозиторий без плана миграции: его адрес встроен в ранее выпущенные приложения.

## Подпись сборок

Windows уже может проверять и скачивать релизы через HTTPS с проверкой контрольной суммы. Текущий выпуск без сертификата: для проверки издателя будущих обновлений нужно настроить подпись. В репозитории Settings → Secrets and variables → Actions добавить WIN_CSC_LINK (сертификат PFX в base64) и WIN_CSC_KEY_PASSWORD. Секреты не передавать в чат и не коммитить.

Для macOS необходимы подпись и нотарификация. В той же секции добавить:

- MAC_CSC_LINK — сертификат Developer ID Application в формате P12, base64.
- MAC_CSC_KEY_PASSWORD — пароль сертификата.
- APPLE_ID — Apple ID для нотарификации.
- APPLE_APP_SPECIFIC_PASSWORD — пароль приложения Apple.
- APPLE_TEAM_ID — идентификатор команды Apple Developer.

Без сертификата Actions создаёт неподписанную macOS-сборку для ручной установки, с отключёнными автообновлениями. Наличие сертификата без данных нотарификации останавливает сборку. При наличии всех данных workflow включает pomodoroMacUpdates в метаданных подписанной сборки. Первую подписанную версию нужно установить вручную поверх неподписанной. Перед выпуском проверить подпись, запуск и обновление на реальном Mac.

## Архитектура и проверки

UpdateService управляет состояниями проверки, загрузки и установки независимо от платформы; electron/updates.ts подключает библиотеку, а renderer получает типизированные данные через проверяемый IPC. Произвольные адреса или команды из renderer не принимаются. Примечания к выпуску показываются как текст.

Тесты проверяют фоновую загрузку без автоматической установки, повторные нажатия, ошибки сети/загрузки/установки, блокировку работающего таймера и сохранение перед установкой. test:update-install проверяет настоящий Electron-адаптер и параметры NSIS /S и --force-run, перехватывая запуск процесса и выход приложения. Полный переход между двумя установленными версиями проверять в отдельной Windows-среде. До такого прогона нельзя считать проверенной фактическую замену установленного приложения.

Источники: [Auto Update](https://www.electron.build/docs/features/auto-update/), [AppUpdater](https://www.electron.build/docs/api/electron-updater.class.appupdater/).
